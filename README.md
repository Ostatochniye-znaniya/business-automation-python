# Остаточные знания — Московский Политех

Приложение для планирования проверок остаточных знаний, заполнения результатов
студентов, формирования графиков и проверки отчётности. Python 3.12+, FastAPI,
Pydantic 2, async SQLAlchemy 2, MySQL 8.4. Frontend — Next.js, React и TypeScript.

Интерфейс основан на ветке [develop Front-end-](https://github.com/Ostatochniye-znaniya/Front-end-/tree/develop)
(исходный commit `89086c3d6e743c7075ebbf718eeaeeb96366eedd`). Используются её компоненты,
стили, оформление и навигация по ролям. Демонстрационные таблицы и адреса C# API
заменены подключением к Python API. Старый статический интерфейс сохранён в
`legacy/frontend-static` и не входит в основную навигацию.

## Запуск через Docker

```powershell
Copy-Item .env.example .env
docker compose up --build -d
```

Замените примерные пароли. `DATABASE_URL` и `MYSQL_*` должны указывать одинаковые
базу, логин и пароль. В контейнерном URL хост — `db`. Спецсимволы пароля должны
быть URL-кодированы. MySQL и backend публикуются только на localhost.

При старте сервис `migrate` выполняет `alembic upgrade head`, затем запускается
backend. База и файлы отчётов хранятся в отдельных постоянных volumes. Обновление
контейнеров не удаляет их. `docker compose down -v` удаляет данные и не используется
для обычного обновления.

- Главная: http://localhost:8000/
- Локальный вход: http://localhost:8000/csh/login
- Отчёты ЛПР: http://localhost:8000/csh/lpr/report
- Документы декана: http://localhost:8000/csh/dof/documents
- Swagger: http://localhost:8000/docs
- OpenAPI: http://localhost:8000/openapi.json
- Health: http://localhost:8000/health

Для демонстрации включите `DEMO_DATA=true` в `.env` и пересоздайте backend:

```powershell
docker compose up -d --force-recreate backend
```

Демоданные загружаются только в development/test, атомарно, без перезаписи
существующих записей. Вход позволяет выбрать демо-администратора, ЛПР,
заведующего кафедрой, преподавателя или гостя. Гость может запросить роль у ЛПР.

## Локальный Python

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
Copy-Item .env.example .env
docker compose up -d db
```

Для backend вне Docker замените `db` на `localhost` в `DATABASE_URL`.

```powershell
.venv\Scripts\alembic upgrade head
.venv\Scripts\python -m uvicorn app.main:app --reload --port 8001
```

Frontend запускается в другом терминале (Node.js 22+, pnpm 11):

```powershell
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend dev
```

Откройте http://localhost:3000/csh/login. Запросы `/csh/api` проксируются к
`http://127.0.0.1:8001/api`; другой адрес задаётся через `BACKEND_URL` перед запуском/сборкой Next.js.
В Docker frontend доступен на порту 8000, backend — на 8001, MySQL — на 3306.

Для локальной генерации PDF нужен Unicode-шрифт: Arial на Windows или пакет
`fonts-dejavu-core` на Linux. Dockerfile устанавливает DejaVu Sans.

Если демоданные не нужны, первого администратора можно создать серверной командой:

```powershell
.venv\Scripts\python -m app.cli --external-id employee-001 --name "ФИО администратора"
```

Команда требует применённых миграций и не изменяет уже существующего сотрудника.
В development также доступен `DEV_USER_ID` для запуска от существующего пользователя.

## Рабочий процесс

1. Администратор вводит подразделения, сотрудников, направления, группы и студентов
   или импортирует сотрудников из CSV/XLSX. Новым сотрудникам назначается GUEST.
2. ЛПР создаёт период, открывает редактирование и составляет рекомендации групп.
3. Заведующий кафедрой выбирает участие рекомендованной группы и две дисциплины.
4. Кафедра дисциплины назначает преподавателя и предлагает дату, время и аудиторию.
   Для чужой кафедры назначение выполняет сотрудник того подразделения.
5. Преподаватель принимает время либо отклоняет с комментарием.
6. Ответственный скачивает согласованный PDF-график с подписью руководителя.
7. Преподаватель заполняет статус участия и результаты каждого студента, завершает
   ведомость, создаёт карточку отчёта, при необходимости указывает преподавателя
   предыдущего семестра и скачивает DOCX.
8. PDF/DOCX загружается на проверку ЛПР. Отклонение требует замечания; после
   исправления файл загружается повторно. Принятый отчёт перед изменением отзывается.
9. ЛПР включает или отключает приём бумажных отчётов для выбранного семестра.
   Электронная версия обязательна всегда. При отключённой бумажной версии
   достаточно принятия электронной; при включённой требуются обе. Печать и
   физическая передача подписанного отчёта выполняются вне системы.
10. ЛПР скачивает сводный CSV и закрывает период. Запись в закрытом периоде запрещена;
    для исправлений ЛПР может переоткрыть его с подходящими сроками доступа.

Приказы и черновики сохраняются в MySQL. Опубликованный приказ нельзя редактировать
или удалять. Статистика главной страницы рассчитывается через сервисы модулей.
Описание формул и соответствие пунктам ТЗ: [docs/requirements.md](docs/requirements.md).

В отчётах доступны фильтры по семестру, факультету, кафедре, дисциплине и статусам.
ЛПР видит все факультеты, декан — только группы своего факультета; ограничение
действует в API, включая прямые запросы и скачивание. Показатель
`at_least_half_participated` вычисляется как `total_students > 0 and participated_students * 2 >= total_students`.
Учитывается статус PASSED, а не величина оценки. Отсутствующие и недопущенные
остаются в знаменателе. В пустой группе результат false.

## Импорт сотрудников

UTF-8 CSV с разделителем `;`, `,` или табуляцией, либо первый лист XLSX.
Заголовки: `external_id`, `full_name`, `email`, `position`, `department_id`.
Обязательны первые два. `department_id` — существующее подразделение.
Весь документ проверяется до записи, повторяющиеся табельные номера отклоняются.
При повторном импорте обновляются сведения сотрудника, его роль сохраняется.
Ошибки и количество обработанных записей доступны в журнале импорта.

```csv
external_id;full_name;email;position;department_id
employee-002;Тестовый сотрудник;employee@example.test;Преподаватель;1
```

По умолчанию отсутствие сотрудника в файле не отключает его. Полная синхронизация
с деактивацией пропущенных записей доступна только администратору с явным параметром
`deactivate_missing=true`; такой файл должен содержать текущего администратора.

## Авторизация и внешние системы

Университетское SSO разрабатывает смежный проект; его готового контракта нет.
Локальный вход разрешён только при `APP_ENV=development` или `test` и отключён в
production. Сессии хранятся в БД как SHA-256-хеши случайных токенов; cookie — HttpOnly,
SameSite=Strict, срок действия 8 часов. Роль и активность проверяются по текущей записи.

Для совместимого провайдера предусмотрен HTTPS RFC 7662 introspection adapter
(`AUTH_INTROSPECTION_URL`, `AUTH_INTROSPECTION_CLIENT_ID`, `AUTH_INTROSPECTION_CLIENT_SECRET`).
`sub` сопоставляется с `User.external_id`; роли из токена не используются.
Настройка этого адаптера не заменяет согласование реального контракта ЛК.

Адреса кадрового API и API учебных планов пока не предоставлены. Доступны mock
providers и ручное ведение справочников. Автоматическая синхронизация с реальными
университетскими системами требует их документированных интерфейсов и доступов.

## Architecture

Router → Service → SQLAlchemy / AsyncSession → MySQL.

Модульный монолит. Каждая сущность принадлежит своему модулю. Зависимости FastAPI
передают сессию сервисам, записывающий use case завершает транзакцию. При ошибке
незавершённая транзакция откатывается при закрытии сессии. Dashboard и экспортные
формы обращаются к публичным сервисам модулей. Нет Repository/UoW, очередей и DI-контейнера.

Роли и принадлежность к подразделению проверяются сервером. Журнал действий
не хранит токены или содержимое файлов. Ошибки приложения преобразуются в HTTP,
ошибки ограничений БД — в 409, неожиданные ошибки — в обезличенный 500 и серверный лог.

## Миграции

```powershell
.venv\Scripts\alembic upgrade head
.venv\Scripts\alembic revision --autogenerate -m "describe schema change"
```

Не используйте `create_all` на рабочей базе. Миграция 0005 добавляет административные
таблицы и поля workflow без удаления существующих frontend, студентов и результатов.
Миграция 0006 добавляет настройку бумажных отчётов по семестру и пересчитывает
итог существующих отчётов. Решения по бумажным версиям сохраняются при отключении приёма.
Перед обновлением рабочей базы сделайте её резервную копию.

## Проверки

```powershell
.venv\Scripts\python -m pytest
.venv\Scripts\ruff check .
.venv\Scripts\ruff format --check .
node --test tests/frontend/*.test.cjs
pnpm --dir frontend exec eslint . --max-warnings=0
pnpm --dir frontend exec tsc --noEmit
pnpm --dir frontend build
```

Backend-тесты используют временную SQLite с проверкой внешних ключей. Для проверки
на MySQL дополнительно выполните миграции и сквозной сценарий на отдельной базе.
CI проверяет Python, frontend, миграции и workflow на MySQL, браузерный процесс
и сборку Docker. Для локального запуска тестов на отдельной MySQL установите
`TEST_DATABASE_URL` на базу `knowledge_verification`: тесты пересоздают её схему,
поэтому рабочая база для этой команды запрещена.

Production workflow использует серверный `.env` и проект Compose
`knowledge-production`; настройте `SERVER_HOST`, `SERVER_USER`, `SSH_PRIVATE_KEY`
в секретах GitHub. Старые preview-workflow сохранены: они относятся к прежнему
окружению Flask и требуют отдельного согласования с администратором общих стендов.

Браузерный сквозной тест запускает отдельный временный HTTP-сервер и временную БД:

```powershell
.venv\Scripts\python -m pip install -e ".[browser]"
pnpm --dir frontend build
.venv\Scripts\python tests/browser/check_frontend.py --output .qa/browser
```

На Windows используется установленный Microsoft Edge. Для Chromium на Linux:
`python -m playwright install chromium`. Тестовые данные не попадают в рабочую базу.
Для теста должен быть свободен порт 8001; он запускает временные FastAPI и Next.js.
Тест проверяет роли, фильтры, порог 50%, бумажную политику и одинаковые зазоры 8 px.
Node-тесты в `tests/frontend` сохраняют проверки прежнего статического интерфейса.

API-операции и их соответствие ТЗ приведены в [docs/requirements.md](docs/requirements.md).
Секреты и `.env` не добавляются в Git; документы отчётов находятся в `storage/`,
который также исключён из Git и Docker build context.
