# business-automation

Flask application foundation with MySQL schema migrations managed by Flask-Migrate
(Alembic).

## Database migrations

Migrations are stored in `migrations/` and must be committed with the code that
changes the database schema. The initial revision deliberately contains no domain

### Local setup

```bash
cp .env.example .env
python -m pip install -r requirements-dev.txt
```

Set `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD` in `.env` for
your MySQL instance. Alternatively, set `DATABASE_URL` to a full SQLAlchemy URL.

Start the database and apply every pending migration:

```bash
docker compose up -d db
flask --app run:app db upgrade
flask --app run:app db current
```

`docker compose up -d` runs the one-off `migrate` service before it starts the
Flask service. The migration revision currently creates only Alembic's
`alembic_version` table, because the domain schema has not been defined yet.

### Creating a schema migration

1. Add or modify SQLAlchemy models.
2. Generate a revision with `flask --app run:app db migrate -m "describe change"`.
3. Review the generated file in `migrations/versions/`; do not apply an
   autogenerated migration without reviewing it.
4. Apply it with `flask --app run:app db upgrade`.
5. Commit the model and migration together.

Useful commands:

```bash
flask --app run:app db history
flask --app run:app db current
flask --app run:app db downgrade -1
```
