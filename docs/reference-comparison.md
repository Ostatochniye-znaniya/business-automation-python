## Приказы

В фронтенде список приказов и черновиков использует статические данные, а кнопка
формирования пока показывает alert. Поэтому фактический контракт взят из
`CreateOrderDto`, `OrderService` и `OrderPdfGenerator` C# develop.

| Возможность | Python |
| --- | --- |
| Отдельный официальный номер, дата, проверяемый семестр | Сохраняются в MySQL; учебный год определяется выбранным периодом |
| Два должностных лица | Обязательны при публикации |
| Сроки сводных отчётов по проверке и анкетированию | Отдельные поля |
| Сроки электронных и бумажных отчётов | Раздельные; бумажный требуется при включённом приёме |
| Подготовка, тестирование, анкетирование, обработка результатов | Все даты из C# контракта, проверка последовательности |
| Таблица / карточки, поиск, черновики | Работают с API, а не со статическими массивами |
| PDF приказа | Основной текст, приложение с рекомендациями, приложение с бланком отчёта |

Сохранён существующий процесс редактирования и удаления черновиков. Публикация
фиксирует данные; существующие неполные приказы не удаляются и не дополняются
вымышленными реквизитами. Для них скачивание возвращает понятную ошибку.
Печатный текст адаптирован к настройке приёма бумажных отчётов и Python-нумерации
семестров (1 — осень, 2 — весна). Это функциональное соответствие образцу,
а не побайтовое совпадение PDF разных библиотек.

## Отчёты

`app/modules/reports/templates/group_report.docx` — неизменённый
`GroupReportTemplate.docx` из указанного commit KnowledgeApp. Заполнение заменяет
только `word/document.xml`, сохраняя остальные части архива побайтово.

- Сохранены объединённые реквизиты, четыре колонки результатов, четыре строки
  итогов и таблица подписей.
- Подставляются год, код направления, программа, дисциплина, группа и полный
  алфавитный список студентов; количество строк расширяется под состав группы.
- Бланк содержит пустые результаты, как C# `GenerateTemplate`.
- Заполненный отчёт дополнительно содержит сохранённые оценки, в том числе 0,
  статусы отсутствия / недопуска, итоги и преподавателя предыдущего семестра.
- PDF содержит те же реквизиты и колонки; длинные списки переносятся с повтором шапки.
- Декан рассматривает и скачивает только отчёты своего факультета; ЛПР видит все.
  Электронная версия обязательна, бумажная зависит от политики периода.

API: `/api/exports/report/{test_id}.docx` и `.pdf`; `?template=true` выдаёт
предзаполненный бланк до завершения ведомости. Заполненный отчёт доступен после
завершения. Приказ скачивается через `/api/orders/{id}/file`.

## Рекомендации

Восстановлены возможности прежней страницы `legacy/frontend-static/pages/groups.html`:
матрица прошлых / текущих / будущих тестирований, курс, фильтры, массовые отметки,
сохранение выбора между фильтрами, отмена, история и выгрузка. Дизайн использует
общие компоненты текущего фронтенда и единый зазор 8 px. Отметки тестирований
не подменяют результаты студентов. Сервер сохраняет проверку версий рекомендаций,
участия группы в периоде и закрытых периодов.
