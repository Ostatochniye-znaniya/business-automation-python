# Границы модулей

Все ORM-модели регистрируются через app.db.base.register_models.
Внешние ключи заданы строками: модулям не нужны импорты чужих ORM-классов.
Dashboard получает данные исключительно через публичные методы сервисов.

Сервисы получают AsyncSession в конструкторе. Запись завершается commit внутри
use case, HTTP-слой не управляет SQL или транзакциями. При ошибке dependency
закрывает session и откатывает незавершённую транзакцию.

Провайдеры возвращают DTO с external_id. Файловый импорт сопоставляет сотрудников
по внешнему идентификатору и использует существующие подразделения. Автоматическая
синхронизация с университетскими API требует их контрактов. Mock providers
служат примером внешнего контракта, а не заполнением рабочей БД.

Отчёт проходит DRAFT → SUBMITTED → APPROVED или REJECTED. Исправление требует
повторной загрузки файла. Бумажная версия принимается отдельно, после электронной.
COMPLETE требует принятия обеих версий. Период OPEN с актуальными сроками доступа
необходим для записи. Сервис PeriodService удерживает блокировку периода до commit.

Назначение преподавателя проверяет принадлежность к кафедре дисциплины; согласование
времени выполняет назначенный преподаватель. Результат может относиться только к
студенту группы проверки. Dashboard и печатные формы используют публичные сервисы.

Все datetime в БД хранятся в UTC без tzinfo. Время графика и границы календарных
периодов интерпретируются по Москве. Роли берутся из БД при каждом запросе.
Локальные сессии хранятся в виде хеша токена и недоступны в production.
