## Правила статистики

Группы: план — рекомендованные, факт — участвующие в выбранном периоде.
Дисциплины: план — две проверки на участвующую группу (ТЗ 2.4), факт — назначенные
неотменённые проверки. Это количество назначений «группа–дисциплина», а не число
уникальных названий дисциплин. Показатели факультета включают дочерние кафедры.
Общий признак завершения требует ненулевого плана и сдачи обеих версий каждого
ожидаемого отчёта. Пустой период не считается завершённым.

Числовые оценки сохраняются без предположения о шкале. Система не пересчитывает
оценки в проценты и не выводит «успеваемость» без согласованной шкалы оценивания.

## Внешние зависимости

Авторизацию через ЛК разрабатывает смежный проект, готового контракта нет.
Локальный вход предназначен для development/test и недоступен в production.
Имеется адаптер проверки Bearer-токена через настраиваемый RFC 7662 endpoint;
это возможность подключения совместимого провайдера, а не утверждённый протокол ЛК.

Адреса кадрового API и API учебных планов не предоставлены. Поэтому предусмотрены
provider-интерфейсы, mock providers, файловый импорт сотрудников и ручное ведение
учебных справочников. Автоматического обращения к реальным системам университета нет.

Деплой на университетский сервер требует настроенных секретов CI, серверного `.env`,
DNS/TLS и доступа администратора сервера. Приложение не изменяет эти системы при разработке.
